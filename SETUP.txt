TimeThreads - getting the project running
==========================================

Firebase is already set up. You do not need to create a Firebase
project. The only thing you add yourself is a small config file
(step 2 below). Follow the steps for your role.

DON'T FORGET TO WORK ON YOUR BRANCH!!! 


EVERYONE: run the app locally
-----------------------------

You need Node.js 22 or newer (https://nodejs.org). Check with:

    node --version

Step 1. Get the code and install, from the repo root:

    git pull
    cd timethreads
    npm install

Step 2. Add the Firebase config (one time only). The config is kept
out of git so GitHub does not send security alerts about it.

  a. In the timethreads folder, make a copy of .env.example and name
     the copy .env.local

         Windows:    copy .env.example .env.local
         Mac/Linux:  cp .env.example .env.local

  b. Find the values. Open
     https://console.firebase.google.com/project/timethreads/settings/general
     scroll down to "Your apps" and pick the TimeThreads web app.
     Firebase shows a block of code containing "const firebaseConfig".

  c. Open .env.local and copy each value from that block onto the
     matching line, after the "=". Leave out the quotes and the
     commas, and do not add spaces:

         Firebase shows        goes on this line in .env.local
         -----------------     ---------------------------------
         apiKey                VITE_FIREBASE_API_KEY
         authDomain            VITE_FIREBASE_AUTH_DOMAIN
         projectId             VITE_FIREBASE_PROJECT_ID
         storageBucket         VITE_FIREBASE_STORAGE_BUCKET
         messagingSenderId     VITE_FIREBASE_MESSAGING_SENDER_ID
         appId                 VITE_FIREBASE_APP_ID

     A finished line looks like this:

         VITE_FIREBASE_PROJECT_ID=timethreads

    You only need to copy whats inside of:  const firebaseConfig = {

Do NOT paste Firebase's code block into firebase.ts or any other file
in the repo. firebase.ts already does the setup and reads the values
from .env.local. Only .env.local is ignored by git.

Step 3. Start the app, still in the timethreads folder:

    npm run dev

Open the address it prints (usually http://localhost:5173). The app
talks to the shared TimeThreads Firebase project, so everyone sees the
same data.

Run "npm install" again whenever you pull and package.json has changed.


USING FIREBASE IN CODE (frontend, backend)
------------------------------------------

The connection lives in timethreads/src/firebase.ts. Do not copy the
config anywhere else. Import what you need from it:

    import { auth, db } from './firebase'

"auth" is Firebase Authentication, "db" is Firestore. Adjust the
relative path if your file is in a subfolder.


DEPLOYING (only if you change rules or publish the site)
--------------------------------------------------------

Everyone on the team is already a member of the Firebase project with
full access.

One-time setup:

    npm install -g firebase-tools
    firebase login

Log in with the Google account that was added to the project.

Then, from the repo root (not the timethreads folder):

    firebase deploy --only firestore:rules     security rules
    firebase deploy --only hosting             the website

The hosting deploy builds the app for you, using the values in your
.env.local, so do step 2 above before you deploy. The live site is
https://timethreads.web.app

Security rules are in firestore.rules at the repo root. Deploying them
replaces the live rules for the whole team, so tell the group before
you do it.


DATA PIPELINE (Python, Admin SDK)
---------------------------------

The pipeline writes to Firestore with a service account key, not the
web config.

1. Open https://console.firebase.google.com/project/timethreads/settings/serviceaccounts/adminsdk
2. Click "Generate new private key" and save the JSON file.
3. Keep it outside the repo, or name it serviceAccount.json so git
   ignores it.

NEVER commit this file. It gives full access to the
database. 

RULES FOR THE WHOLE TEAM
------------------------

- Free plan only. Never upgrade the project to Blaze and never add a
  card. Everyone has full access to the project, so any one of us
  could do this by accident.
- Do not delete the project, the database, or other people's data in
  the Firebase console without checking with the team first.
- No Cloud Functions. They need the paid plan.
- The free plan allows 50,000 reads and 20,000 writes per day, shared
  by all of us. Do not leave a loop reading or writing the whole
  database.


IF SOMETHING GOES WRONG
-----------------------

"Missing or insufficient permissions"
    You are not signed in to the app, or the security rules block that
    read or write. Check firestore.rules.

"Missing Firebase config" or a blank page
    The .env.local file is missing, is in the wrong folder (it must be
    inside timethreads, next to package.json), or has an empty line.
    The error names the values that are missing. Redo step 2, then
    stop and restart "npm run dev".

"firebase: command not found"
    Run: npm install -g firebase-tools
    or try
    npm install firebase

"firebase deploy" says you have no access to the project
    You are logged in with a different Google account than the one
    added to the project. Run "firebase logout", then "firebase login"
    with the right account.

"npm run dev" fails right after a pull
    Run "npm install" inside the timethreads folder and try again.
